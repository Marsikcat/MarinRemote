# MarinRemote

Удалённый доступ к ПК с Windows без своих серверов: экран, мышь, клавиатура, буфер обмена
и файлы. Соединение — QUIC через [iroh](https://iroh.computer): ПК находят друг друга по
публичному ключу. iroh сам пробивает NAT, а если не получилось, гонит зашифрованный трафик
через публичные ретрансляторы n0. Ретранслятор видит только шифротекст.

В одной программе две роли: **«Этот ПК»** (к нему подключаются) и **«Подключиться»**
(вы подключаетесь к другому ПК).

> **Версия 0.1.0 — MVP:** доступ к ПК, пока на нём вошёл пользователь и запущен MarinRemote.
> Служба Windows для экрана входа и UAC, звук и подписанные обновления — второй этап
> (см. «Ограничения MVP»).

## Установка

Скачайте `MarinRemote-Setup-X.Y.Z.exe` и запустите.
- **Без прав администратора:** программа ставится в `%LOCALAPPDATA%\Programs\MarinRemote`
  для текущего пользователя.
- **Можно отметить** ярлык на рабочем столе и «Запускать вместе с Windows». Автозапуск нужен,
  чтобы к ПК можно было подключиться без вас.
- **Удаление** — через «Параметры → Приложения» как обычно. Данные (ключ устройства, контакты,
  журнал) остаются в `%APPDATA%\MarinRemote`.

**Автозапуск.** «Запускать вместе с Windows» включается и выключается в «Настройках» или
галочкой в меню значка в трее. Это одна и та же настройка. С включённым «При автозапуске —
сразу в трей» программа стартует без окна и тихо ждёт подключений.

При первом запуске Windows может спросить про брандмауэр. Через интернет всё работает и без
разрешения. Для прямых подключений в локальной сети есть кнопка «Настройки → Открыть порты
в брандмауэре» (спросит права администратора).

### Сборка установщика

Нужны venv с `requirements.txt` и `pyinstaller`, а также
[Inno Setup 6](https://jrsoftware.org/isinfo.php).

```bat
venv\Scripts\python -m pip install pyinstaller
venv\Scripts\python tools\build.py
```

Результат: `dist\MarinRemote\` (программа) и `dist\MarinRemote-Setup-X.Y.Z.exe` (установщик).
В GitHub Actions то же самое делает workflow «build» (вручную или по тегу `v*`); установщик —
в артефактах прогона.

## Запуск из исходников

Нужен Python 3.12 для Windows 10/11.

```bat
python -m venv venv
venv\Scripts\python -m pip install -r requirements.txt
venv\Scripts\pythonw app.py
```

Данные лежат в `%APPDATA%\MarinRemote`: `settings.json` (ключ устройства, контакты,
доступ), `journal.jsonl`, `auth_state.json`, `app.log`.

### Два экземпляра на одном ПК (для проверки)

`tools\run_two.bat` запускает экземпляры 1 и 2 (`MARINREMOTE_INSTANCE=1/2`). У них свои
порты, а данные лежат в `%TEMP%\MarinRemote-dev-N`. Настоящий профиль они не трогают.

### Тесты

```bat
venv\Scripts\python -m pip install pytest
venv\Scripts\python -m pytest -q
```

Тест с настоящим захватом экрана включается переменной `MARINREMOTE_REAL_SCREEN=1`.
Кадры при этом остаются в памяти теста и никуда не сохраняются.

`tools\screens.py` рисует окна программы в PNG без вывода на экран.
`tools\kill_encoders.py` закрывает оставшиеся процессы кодировщика этого проекта.
Обычно они и так заканчиваются вместе с приложением.

## Как подключиться

1. На удалённом ПК: «Этот ПК» → «Копировать код» (`mr-…`). Передайте код любым способом.
2. На своём: «Подключиться» → вставьте код. ПК в той же сети (и в Radmin VPN) видны
   в списке и без кода.
3. На удалённом ПК появится окно «… хочет подключиться». Там отмечают права и жмут
   «Разрешить». Если 30 секунд никто не ответит — отказ.
4. Чтобы дальше подключаться в один клик:
   - **на своём ПК:** «Сохранить в контакты»;
   - **на удалённом:** в окне запроса отметьте «Запомнить это устройство → дальше
     подключаться без подтверждения».

   Чтобы подготовить это заранее, когда у удалённого ПК никого не будет: там «Доступ» →
   «Добавить устройство по коду» и вставьте код своего ПК.

### Ссылки

«Этот ПК» → «Ссылка» копирует `marinremote://mr-…`. Щелчок по ней (в мессенджере, в
браузере, в «Выполнить») открывает MarinRemote — уже запущенную копию или новую — и
спрашивает «Подключиться к …?» с отпечатком и запрашиваемыми правами. Без вашего «Да»
подключения нет. То же из командной строки: `MarinRemote.exe --connect <код или ссылка>`.

Ссылки регистрирует установщик (`HKCU\Software\Classes\marinremote`, без прав
администратора; при удалении ключ убирается). Копия, запущенная из другой папки,
перехватывает ссылки, только если зарегистрированной программы больше нет.

### Связать свои ПК

Оба ПК в одной сети (или в Radmin VPN). На одном: «Подключиться» → в списке «В локальной
сети» нажмите **«Связать»** у другого ПК (или «⋯» → «Связать» у контакта). На обоих экранах
появится один и тот же шестизначный код. Сверьте его и нажмите «Связать» на обоих ПК — каждый
запомнит другой («сразу», с отмеченными правами) и добавит в контакты. Дальше подключение
в обе стороны в один клик, без подтверждения и пароля.

Код получается из ключей обоих ПК и случайных чисел обеих сторон, причём тот, кто
связывается, обязуется своим числом раньше, чем увидит чужое. Поэтому подставной ПК в сети
не может заранее подобрать ключ под совпадающий код: не совпало — нажмите «Отклонить».

## Картинка

- **Захват и кодирование.** Захват через DXGI Desktop Duplication, кадры сразу идут в NVENC
  на видеокарте. Без NVIDIA кодирует x264 на процессоре. Кодировщик — отдельный процесс,
  привязанный к приложению: он не переживёт MarinRemote даже при аварии.
- **Низкая задержка:**
  - без B-кадров и lookahead;
  - ключевые кадры только по запросу;
  - если зритель отстаёт, хост выбрасывает целые кадры и начинает со свежего ключевого,
    а не копит очередь.
- **Курсор** передаётся отдельно (позиция датаграммами, форма — при смене) и рисуется у зрителя.
- **В окне сеанса:**
  - выбор монитора;
  - качество: «Авто» (опускается, когда связь не тянет, и сама поднимается обратно, когда
    она наладилась), «Плавно» 60 к/с, «Чётко» 30 к/с, «Экономно» 720p;
  - на весь экран — Ctrl+Alt+Enter (без управления ещё и F11);
  - статистика: к/с, Мбит/с, RTT, задержка от захвата до показа.
- **Свёрнутое окно** не получает кадров.
- **Неподвижный экран ничего не стоит:** неизменившиеся кадры не кодируются, не передаются
  и не декодируются. Курсор при этом двигается как обычно.
- **Монитор на другой видеокарте**, где Windows отзывает Desktop Duplication, сам
  переключается на Windows.Graphics.Capture (тоже на видеокарте, с пропуском неизменившихся
  кадров). Если и её нет — на GDI.

Замер на одном ПК (два экземпляра, 1920×1080, NVENC): от захвата на хосте до показа
у зрителя — **9–13 мс**. Неподвижный рабочий стол — меньше 1 Мбит/с при 60 к/с.

## Мышь и клавиатура

С правом «управление» в окне сеанса включено **«Управление»**: мышь над картинкой и клавиши
идут на удалённый ПК.
- **Курсор** — ваш собственный, в форме удалённого, поэтому без задержки.
- **Клавиши** передаются скан-кодами: печатает раскладка удалённого ПК, как с подключённой
  к нему клавиатурой.
- **«Системные клавиши»** (включено по умолчанию): Win, Alt+Tab, Alt+F4 и прочие уходят
  на удалённый ПК, пока окно сеанса впереди.

  Чтобы вернуть их своему ПК, щёлкните мышью вне окна или выключите переключатель.
  **Ctrl+Alt+Enter** — полный экран.
- **Что отпускается само.** Если окно потеряло фокус, сеанс оборвался или его отключили,
  удалённый ПК отпускает всё, что было нажато. Залипших Ctrl и Shift не будет.
- **Чего не перехватить:**
  - окна MarinRemote на удалённом ПК удалённо не нажимаются — это защита;
  - окна, запущенные от администратора, запрос UAC и экран блокировки недоступны
    (ограничение Windows). Зритель видит об этом предупреждение.
- **«Действия»** (с правом управления): заблокировать экран, перезагрузить, выключить —
  каждое после подтверждения у зрителя. Перезагрузка и выключение идут через 30 секунд
  с уведомлением Windows; на удалённом ПК появляется окно с кнопкой «Отменить», отменить
  можно и из меню «Действия». Разблокировать экран удалённо в этой версии нельзя: экран
  блокировки защищён, войти может только человек у того ПК.
- **«Забрать управление».** На панели сеанса и на странице «Этот ПК» у каждого сеанса с
  управлением есть кнопка «Забрать управление»: мышь и клавиатура зрителя перестают
  действовать (всё нажатое отпускается), смотреть он продолжает и видит об этом сообщение.
  «Вернуть управление» отдаёт его обратно — но не больше прав, чем было выдано при входе.

## Файлы

**«Файлы»** в окне сеанса — две панели: этот ПК и удалённый.
- **Передать:** кнопки «Отправить →» и «← Скачать», перетаскивание между панелями
  и из Проводника.
- **Файлы, брошенные прямо на картинку,** уходят в открытую справа папку, а если она
  не открыта — в «Загрузки» удалённого ПК.
- **Папки** передаются целиком.
- **На удалённом ПК:** новая папка, переименование, удаление (в корзину).

**Как идёт передача:**
- каждый файл — своим потоком, без ограничения размера, с приоритетом ниже картинки и мыши;
- после обрыва передача продолжается с того же места сама;
- после перезапуска программы — кнопкой «Продолжить»;
- файл занимает своё место, только когда SHA-256 совпал на обоих концах;
- отмена убирает недокачанную часть.

**Доступ.** Удалённый ПК показывает только папки, открытые на нём в «Доступ → Папки для
файлов» (по умолчанию — папка пользователя). Выйти из них нельзя ни через `..`, ни через
ярлыки и ссылки (junction, symlink), ни через UNC-пути. Каждая передача и каждое изменение
пишутся в журнал хоста.

**Замер на одном ПК, 1 ГБ:**
- скачивание и загрузка — около 210 МБ/с;
- с обрывом посередине — 137–148 МБ/с, докачка с места обрыва, SHA-256 совпал;
- картинка во время передачи — 51–58 к/с, задержка ≈ 18 мс (без передачи ≈ 10 мс).

## Буфер обмена

С правом «буфер обмена» текст, скопированный на одном ПК, вставляется на другом, в обе
стороны. Переключатель «Буфер обмена» в окне сеанса.
- **Что уходит.** Только то, что скопировано во время сеанса: скопированное раньше, например
  пароль, не отправляется.
- **Что не уходит.** Копии, которые программы помечают как частные (менеджеры паролей делают
  так через `ExcludeClipboardContentFromMonitorProcessing`), остаются на своём ПК.
- **Ограничения:** только текст, до 1 млн символов.

## Журнал

Вкладка «Журнал» (и файл `journal.jsonl`) показывает:
- кто и когда просил подключиться и что решили;
- сеансы с правами, способом входа и длительностью;
- неудачные пароли;
- действия сверх прав, ввод в окна MarinRemote и аварийные отключения;
- каждую передачу файла: путь, размер, SHA-256, итог, с какого места продолжили;
- изменения файлов и папок, смену доступа.

Есть фильтры («Подключения», «Файлы», «Защита», «Настройки доступа») и поиск по
устройству, отпечатку или пути. Журнал хранит до двух файлов по 5 МБ.

## Порты

| Порт | Протокол | Зачем |
|---|---|---|
| 8895 (+100 на тестовый экземпляр) | UDP | QUIC: всё содержимое сеансов. Если порт занят, берётся случайный |
| 8894 | UDP | поиск в локальной сети, общий для всех экземпляров |
| случайный | TCP, только 127.0.0.1 | кодировщик → приложение |

С MarinCall (8890, 8891) не пересекаются: обе программы можно запускать одновременно.
Через интернет хватает исходящих соединений. Входящий порт нужен только для прямого
подключения в локальной сети, если брандмауэр не пропустил программу.

## Модель безопасности

- **Личность = ключ.** ID устройства — его публичный ключ Ed25519. QUIC/TLS доказывает
  ключ при каждом соединении и шифрует всё.
- **Секретный ключ** в `settings.json` хранится только зашифрованным через Windows DPAPI для
  вашей учётной записи на этом ПК. Скопированный файл на другом ПК или под другим
  пользователем бесполезен: выдать себя за ваше запомненное устройство с ним нельзя.
  Программа такой ключ не использует и создаёт новый.
- **Решает хост.** По умолчанию каждое подключение подтверждает человек у ПК:
  30 секунд, галочки прав (просмотр / управление / файлы / буфер обмена), по таймауту — отказ.
- **Без подтверждения** входят только запомненные устройства:
  - режим «сразу» — их ключ и есть пропуск;
  - режим «по паролю» — нужен пароль, заданный на хосте. Хранится хэш argon2id (соль,
    256 МБ, 3 прохода).

  Устройству, которого нет в списке, пароль не поможет. Всё это выключается одним
  переключателем «Пускать запомненные устройства без подтверждения».
- **Подбор пароля:**
  - на устройство 3 попытки без задержки, дальше 2, 4, 8 … с, до 15 минут;
  - больше 20 неудач за 10 минут от кого угодно — пауза для всех;
  - счётчики переживают перезапуск.
- **Окна подтверждения не спамятся:** одно на устройство, три сразу; после отказа —
  минута тишины.
- **До входа хост ничего не принимает.** Датаграммы и стримы, отправленные до входа,
  отбрасываются по метке сеанса.
- **Права проверяет хост** на каждом сообщении. Действия сверх выданных игнорируются
  и пишутся в журнал. Право, которое хост забрал на ходу, хост может вернуть, но выдать
  больше, чем при входе, нельзя; то, что зритель успел отправить до того, как узнал об
  этом, тихо отбрасывается.
- **Сеанс видно:**
  - красная рамка по краю экранов (зрителю её не видно, клики проходят сквозь неё);
  - панель поверх окон «кто подключён · права · Отключить»;
  - значок в трее с красной точкой.
- **Аварийная клавиша** `Ctrl+Shift+Alt+F12` (меняется в «Доступе») рвёт все сеансы
  мгновенно, где бы ни был фокус. После неё повторный вход требует нового подтверждения.
- **Повторный вход после обрыва.** Хост выдаёт зрителю одноразовый токен, привязанный
  к его ключу. Если сеть пропала, в течение минуты он входит снова без подтверждения.
  «Отключить», аварийная клавиша и уход зрителя токен аннулируют.
- **Настройки доступа блокируются**, пока подключены с правом управления: их нельзя
  поменять удалённо.
- **Удалённый ввод в окна MarinRemote** отбрасывается: зритель не может сам себе нажать
  «Разрешить» или поменять доступ.
- **Файлы** — только внутри разрешённых папок. Путь проверяется по тексту и по настоящему
  пути открытого файла, удаление — только в корзину.
- **Буфер обмена** — только скопированное во время сеанса, без частных копий менеджеров паролей.
- **Блокировка, перезагрузка, выключение** — только с правом управления (тот, кто может
  печатать на ПК, мог бы сделать то же из меню «Пуск»), с отложенным на 30 секунд
  выполнением и кнопкой «Отменить» у человека за ПК.
- **Связывание ПК** — то же подтверждение, что и при подключении, плюс шестизначный код
  для сверки на обоих экранах; связывание само по себе сеансом не является.
- **Журнал** («Журнал», `journal.jsonl`) — всё перечисленное выше.

Протокол подробно: [docs/PROTOCOL.md](docs/PROTOCOL.md).

## Ограничения MVP

- Программа работает с правами обычного пользователя. Windows (UIPI) не даёт такому
  процессу управлять окнами, запущенными от администратора. Запрос UAC, экран блокировки
  и экран входа тоже недоступны. Нужна служба от имени SYSTEM — это второй этап.
- Доступ работает, пока пользователь вошёл в систему и MarinRemote запущен.
- Ctrl+Alt+Del и Win+L Windows не даёт перехватить и передать.
- Буфер обмена — только текст. Звука с удалённого ПК нет.
- Обновлений нет: новую версию ставят новым установщиком поверх старой.
- Замеры сделаны на одном ПК (два экземпляра). Связь через ретранслятор n0 и медленные
  каналы проверены только логикой и тестами, не живым замером.

**Второй этап** (архитектура под него уже готова: ядро хоста без Qt, захват и ввод отдельно):
- служба Windows от имени SYSTEM, которая запускает помощника в сеансе пользователя:
  доступ после перезагрузки, на экране входа и к UAC;
- установка с правами администратора;
- звук с удалённого ПК;
- обновления с подписью, как в MarinCall.
